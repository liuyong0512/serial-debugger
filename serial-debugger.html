串口读取错误
最常见原因是波特率与设备不一致；请同时核对校验位、数据位、停止位。其次检查 TX/RX 是否交叉接、是否共地、电平是否匹配（TTL 3.3V/5V 与 RS232 不能直连）以及线缆和干扰。

使用说明与注意事项
  • ANSI 彩色（默认开）：文本模式下自动解析设备发来的 ANSI 转义色码（如 ESC[1;31m 红色粗体、ESC[0m 重置），把颜色、粗体、下划线等样式真正显示出来，适用于 Linux shell / 日志那种带色彩的终端输出；支持 16 色、亮色、256 色与 RGB 真彩色。若设备输出的是二进制或被误判定，可取消勾选，按原始文本显示。
  • 交互输入（推荐）：接收框本身即可输入——直接点进接收框末尾的输入行打字，内容显示在接收内容里，按一次 回车 即发送，回复紧接其后显示，像真实终端一样对话；输入为空时单独按回车会发送行尾字符（行尾设为“无”时发送单个 CR），可用于设备要求“按回车继续”的场景；↑ / ↓ 翻历史、Esc 清空。格式与行尾沿用发送区的设置。取消勾选“交互输入”可关闭框内输入行。
  • 列表为空是正常的：浏览器出于安全不会自动枚举所有串口，必须点击“选择串口…”并在弹窗中勾选设备完成授权；之后用“刷新列表”即可恢复。
  • 如果授权弹窗里找不到设备：先在 Windows 设备管理器 → “端口 (COM 和 LPT)”中确认设备已出现；USB 转串口芯片（CH340 / CP210x / FTDI 等）需先安装系统驱动；同时关闭占用该串口的其他程序（如串口监视器、烧录工具）。
  • 出现 Buffer overrun（缓冲区溢出）：这是浏览器接收缓冲一时的溢出，多发生在设备刚上电/首帧猛发数据时，属于可恢复错误——工具已增大接收缓冲区并静默续读，不会中断串口，也不会显示任何提示。若接收数据仍有缺失，可降低设备发送速率或让设备上电后延时再发。
  • 出现 framing error（帧错误）：优先核对波特率，其次核对校验位 / 数据位 / 停止位；确认 TX 与 RX 交叉相接、双方共地、电平一致（TTL 与 RS232 需电平转换）。可勾选“出错自动重连”，或使用错误提示中的 9600 / 115200 快捷按钮重试。
  • 9600 报 Break received 而 115200 乱码，说明两个速率都不对。点“扫描波特率…”可自动尝试 2400 ~ 921600（含 74880）并按数据质量推荐；若仍无结果，优先检查 TX/RX 是否交叉、是否共地、设备是否正在持续发送。
  • 打开时提示 Failed to open serial port：串口属于独占资源，先关闭其他占用它的程序（Python 工具、串口监视器、烧录工具）和其他浏览器标签页；也可在错误提示中点“关闭流控重试”或“重置端口授权”。
  • XMODEM：接收时本工具先发 C 请求 CRC，无响应自动退回 NAK 校验和；支持 128 字节与 1K（STX）包。发送时等待接收方发 C 或 NAK 后开始，末尾发 EOT。传输期间原始字节不会刷到接收区，只显示协议日志。
  • 一个串口同一时间只能被一个页面占用，关闭其他标签页中的串口后再打开。
  • HEX 发送支持空格、逗号、0x 前缀等写法，例如 48 65 6C 6C 6F 或 0x48,0x65。
  • 浏览器不会主动向你发送“串口被拔出”的提示，若通信中断请检查设备并重新打开串口。
  • 所有参数设置与快捷指令会自动保存在本地浏览器中。
